## 部署布局

> **t_03 / t_11 部署边界（强制）**
>
> - `t_03`（控制端）运行完整 A4Diag：Agent、LangGraph 运行时、模型端口、审批、策略引擎、审计和插件管理器。
> - `t_11`（隔离沙箱目标）只安装最小远程 helper 和受限执行账户；不部署控制端、审批系统、插件管理器或完整 A4Diag 服务。
> - `t_03` 不能访问已注册目标以外的机器；`t_11` 不持有任何可写其他主机的凭据。

## 启用写能力前必须在一次性目标上执行的人工验收

### 1. 只读验收

```bash
sudo ./install.sh --offline /path/to/release-dir
sudo a4diag self-check --offline          # global_mode: read_only, targets: []
sudo a4diag init --input target-request.json
sudo a4diag self-check --offline          # 已注册目标，但仍为只读
```

### 2. 低风险执行

在 `a4diag init` 通过明确的 `ENABLE` 设置 `write_enabled` 并开启 `auto_execute_low: true` 后，确认 LOW 计划执行成功，报告状态为 `succeeded` 且残余风险为零。

### 3. 高风险审批

```bash
sudo a4diag approvals list --json
sudo a4diag approvals show <transaction>
sudo a4diag approvals approve <transaction> --digest <digest>
```

确认审批前 executor dispatch 为零，审批后恰好为一次。

### 4. 失败与回滚

通过 chaos 测试注入 executor 崩溃，确认 `execution_unknown` 永远不会重放。使用 `A4DIAG_INJECT_FAILURE=before_switch` 安装错误发布包，并确认 `/opt/a4diag/current` 仍指向上一版本。
