# A4Diag v0.4.0 release candidate checklist

Status: **release candidate — publishing is a separate, explicitly
authorized action.** A missing required CI job or an unexecuted real-environment
gate leaves the corresponding item unchecked and blocks publication.

## Deployment layout (what deploys where)

> **t_03 / t_11 部署边界（强制）**
> - `t_03`（控制器）运行**完整** A4Diag：Agent、LangGraph 运行时、模型端口、审批、策略引擎、审计、插件管理器。
> - `t_11`（隔离沙箱目标）只安装**最小远程 helper 和受限执行账户**：仅作为被诊断/被执行的目标，运行受限 helper 与一个受限执行账户；**不部署** controller、审批系统、插件管理器或完整 A4Diag 服务。
> - `t_03` 不能访问除已注册目标以外的任何机器；`t_11` 不持有任何可写其他主机的凭据。

| Host | Contents |
| --- | --- |
| Controller host `t_03` (or its equivalent) | Full A4Diag controller: `a4diag` core wheel + `a4diag_builtin_plugins` wheel + verified dependency wheelhouse under `/opt/a4diag/releases/<version>`, atomic `/opt/a4diag/current` symlink, hardened systemd units (`a4diag-core.service` running `a4diag serve`, `a4diag-plugin@.service`/`.socket`, `a4diag-cleanup.service`/`.timer`), `/etc/a4diag` read-only config, `/var/lib/a4diag` state, approvals, policy, audit, plugin registry. |
| Sandbox target `t_11` | ONLY the minimal remote helper and a restricted execution account registered as a target of `t_03`. No controller, no approval system, no plugin manager, no full A4Diag service. The helper runs under a dedicated restricted account with no access to any other host. |
| Optional components | Notification plugins (`notification-cli`, `notification-smtp`, `notification-webhook`, `notification-flashduty`), `transport-ssh`, `capability-files`, `capability-services`, `capability-packages`, `model-openai-compatible` — each is a separate registered plugin instance on `t_03` with its own socket and declared permissions; none is enabled by default. |

## Manual acceptance steps to run on a disposable target before enabling writes

1. **Read-only acceptance**
   ```bash
   sudo ./install.sh --offline /path/to/release-dir
   sudo a4diag self-check --offline          # global_mode: read_only, targets: []
   sudo a4diag init --input target-request.json
   sudo a4diag self-check --offline          # target registered, still read_only
   ```
2. **Low-risk execution** (after `a4diag init` sets `auto_execute_low: true` and
   `write_enabled` via explicit `ENABLE`): confirm a LOW plan executes and the
   report shows `succeeded` with zero residual risk.
3. **High-risk approval** (HIGH plan):
   ```bash
   sudo a4diag approvals list --json
   sudo a4diag approvals show <transaction>
   sudo a4diag approvals approve <transaction> --digest <digest>
   ```
   Confirm zero executor dispatch before approval and exactly one after.
4. **Failure + rollback**: inject an executor crash (chaos suite) and confirm
   `execution_unknown` is never replayed; `sudo ./install.sh --offline` a bad
   release with `A4DIAG_INJECT_FAILURE=before_switch` and confirm
   `/opt/a4diag/current` still points at the previous version.
