# A4Diag v0.4.0 已知限制（历史）

以下内容记录 v0.4.0 的历史限制，不会削弱安全保证。当前版本的能力应以 v0.4.2 发布说明和部署文档为准。

## 平台

- **不支持 Docker、Kubernetes 或非 systemd 主机。** 单元清单、安装器和 smoke 测试只面向受支持的 Alibaba Cloud Linux、Rocky Linux、AlmaLinux、RHEL、Ubuntu 和 Debian systemd 发行版。
- **不自动重建虚拟机。** 一次性测试环境由管理员提供；测试套件不会自行创建、重建或销毁虚拟机。
- **不支持 Windows。** 运行时、安装器、服务隔离和发布证据只面向受支持的 systemd Linux 发行版。

## 信任与恢复

- **管理员必须信任已安装的执行插件。** 管理员注册的 capability 插件会使用其 manifest 声明的权限运行。除 systemd 单元隔离和声明的 `permissions`、`network_access`、`secret_refs` 外，Agent 不会为插件进程增加另一层沙箱。
- **无法远程恢复失联或已重装的目标。** 目标不可达或被重装后，Agent 报告 `target_identity_unavailable` 或 `policy_denied`，并要求管理员重新注册；系统不会自动重新注册或重新执行。
- **每项 HIGH 操作都需要 CLI 审批。** 不存在自动批准路径；即使模型声称风险为 LOW，具有 HIGH 风险下限的操作仍保持 HIGH。

## 运行限制

- **结果未知时停止。** 无法确定 effect 结果时，事务停止为 `execution_unknown` 并进入 reconcile，绝不重放；后续步骤由人工决定。
- **旧读取器会把 v3 操作报告归类为异常。** 原因是状态词汇已经改变；旧 v0.3 报告仍可读取。
- **通知依赖已注册插件。** 核心程序不直接发送邮件、Webhook 或 FlashDuty，通知投递由对应插件负责。
- **v0.4.0 的 capability executor 已通过插件 RPC socket 接线；collector、model 和 notification port 在插件 host 提供相应方法前保持 fail-closed。** `a4diag serve` 是 `a4diag-core.service` 的命令，`a4diag-plugin --instance %i` 是 `a4diag-plugin@.service` 的命令；两者可以组装生产运行时。没有目标的默认安装会启动并保持只读。实时 socket 连通性、transport host、model host 和 notification host 是当时仍需完成的生产集成步骤。
