# A4Diag v1.1.0

本版整合 Linux 受控修复分支与诊断可靠性加固。控制端、内置插件、目标端统一为 1.1.0；默认仍为只读。它不是任意命令执行器，也不会自动扩大已有目标授权。

## 主要变化

- 增加目标端独立修复 profile、签名请求、持久化作业及效果记录。进程中断后先查询和核对既有作业；未知执行结果不盲目重放。
- 磁盘清理仅作用于登记的缓存目录和限额，控制写入者并验证实际可用空间；删除属于不可逆效果，不宣称可以回滚。
- 服务修复、精确 Docker 容器、绑定 owner UID 的 Podman 容器、精确 UID 的 Kubernetes Deployment 经过独立健康检查与持续观察后才判定恢复。恢复镜像使用 UID/resourceVersion/旧镜像条件更新；并发变化时拒绝覆盖。
- 告警持久化保存脱敏后的请求，增加租约、重试退避及次数上限。单条故障不阻断后续告警；Alertmanager 暂时不可用或告警已消失时，已入队请求仍可处理。旧版没有请求正文的未完成记录只尝试恢复检查点，不能安全恢复则明确抑制，绝不猜测重放。
- 日志增加 JSON 字段、数据库连接凭据和 PEM 私钥形态脱敏。脱敏是已知格式与已知秘密值的防线，不保证识别所有任意格式的秘密；管理员仍须限制采集范围和模型数据出口。
- Kubernetes 按 Deployment selector 分页读取，再核对 Deployment → ReplicaSet → Pod 的 UID 归属链。关联所属对象的事件，优先采集异常 Pod 的日志；总时间、页数、条数、响应体和日志量均有上限，部分证据显式标记。
- 模型必须引用已采集证据的精确原文。控制端核对来源、资源、完整性、时间和引用内容，模型自报分数单独保留为 `model_confidence`；伪造、过期、缺失或截断证据不能通过引用校验。

## 证据评分不是根因概率

`diagnosis.confidence` 在生产模型接口中改为确定性证据支持评分：有效单一来源为 0.7，至少两个不同 kind/resource 来源为 0.85，存在已引用反证时最多 0.5，无有效支持为 0。来源数量不等于因果独立性；引用匹配只能证明原文存在，不能证明模型推断正确，也不能发现模型刻意遗漏的反证。报告明确标记 `hypothesis_not_causal_proof`，不输出“100% 根因已确定”的保证。

证据有效期为 300 秒；等待审批后再次检查。超过有效期需重新诊断，不会直接使用旧证据写入。已引用反证始终阻止进入修复，不受低阈值配置影响。原有 `minimum_confidence` 现在对证据支持评分生效：设置高于 0.85 会阻止本版自动放行。评分不代替风险策略、人工审批、双端授权、执行前核对或修复后健康检查。

## 支持边界

Python 3.11、x86_64 Linux；控制端 systemd 247+。Kubernetes 仅支持已登记且满足安全约束的 Deployment，不覆盖任意集群资源、GitOps 控制器或带不受支持存储的工作负载。APT 自动修复、网络自动改写、Jev 集成尚未实现，不属于本版已交付能力。详细边界见 [支持矩阵](https://github.com/zhuzihan60/agent/blob/v1.1.0/docs/testing/remediation-matrix.md)。

## 升级顺序

1. 暂停新写请求，将控制端设为只读。备份配置、密钥、审计及 SQLite 状态；核对未完成事务和目标端作业，不能仅凭控制端进程停止就认为目标作业已结束。
2. 先升级目标端，再升级控制端与内置插件，三者保持 1.1.0。已有配置和权限不会自动扩大；新增修复 profile 需要管理员在双端明确登记。
3. 告警数据库首次启动时新增兼容字段。不要通过删除数据库来解除去重或重新触发有副作用的历史事务。
4. 模型需支持新增的 `evidence_refs` 结构。旧模型输出可以被解析，但缺少有效引用会降级为证据不足；保持只读验证采集、引用、身份及报告后再启用有限写策略。
5. 降级不是直接覆盖二进制：先处理完本版作业，并按升级前备份恢复相匹配的三端版本和状态；不要让旧运行时解释新作业。

## 发布检查与资产

分支构建和正式签名发布均依赖普通回归、独立特权回归、真实 systemd/SSH 链路及四组真实修复验收（systemd/磁盘、Docker、Podman、Kubernetes）。真实验收必须实际执行，出现跳过即失败；JUnit 与执行日志保留为流水线资产。安装矩阵与真实故障恢复矩阵分开说明，安装成功不代表所有适配器已经验证。

正式流水线还验证发行版安装、签名和篡改拒绝。Release 提供两端归档、两份归档签名、两端安装脚本和公钥，共七个资产；不包含私钥或实验室配置。
