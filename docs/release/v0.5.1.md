# A4Diag v0.5.1 发布说明

v0.5.1 修复在真实 WSL、systemd、SSH 和 DeepSeek 测试中发现的服务恢复阻断问题。控制端、内置插件和目标端统一升级为 0.5.1。

## 修复

- 为插件生成长度受限、按实例区分的 systemd 动态账户，解决默认模型实例名称过长导致服务无法启动的问题。
- 插件 RPC 支持合法有限小数，使模型置信度可以进入诊断、计划和审查流程；继续拒绝 NaN、无穷大及溢出数值。
- 模型默认输出预算从 1024 提升至 4096 token，减少推理模型输出被截断的问题；截断或不符合 Schema 的结果仍被拒绝。
- 明确验证和撤销元数据的含义：可逆操作使用已登记的撤销生命周期恢复准备阶段记录的状态，模型不能编造命令或准备标记。
- 未单独配置主机密钥摘要时，SSH 传输保留目标经受信连接返回的密钥摘要，避免控制端和目标端计算不同身份指纹。严格 known_hosts 检查保持启用。

## 升级

1. 暂停新修复请求，将控制端设为只读，备份配置、密钥和持久化状态；先核实并处理未完成事务。
2. 先升级目标端，再升级控制端及内置插件，三者使用同一版本。
3. 使用原始初始化输入运行 `a4diag init --input /安全路径/init.json`，重新生成插件动态账户、凭据配置及目标身份登记。
4. v0.5.0 中未配置主机密钥摘要的 SSH 目标，其登记指纹可能因本次修复变化。通过受信渠道核对目标身份后重新初始化，不要重放旧指纹绑定的审批或票据，也不要直接删除未知事务锁。
5. 保持只读完成连接和证据检查，再对限定测试服务验证恢复后启用所需写策略。

控制端仍要求 systemd 247+，两端使用 Python 3.11。完整环境要求见[安装指南](https://github.com/zhuzihan60/agent/blob/v0.5.1/docs/install.md)。

## 验证范围

修复代码已在两套隔离的 Ubuntu 24.04 WSL2 环境中连接真实 DeepSeek `deepseek-flash` 验证：停止演示 HTTP 服务后，完成证据采集、模型诊断、计划、审查、签名 prepare/apply/verify，最终服务为 active，HTTP 返回 200 且正文匹配，事务结果为 `succeeded`、业务检查为 `business_recovered`。测试结束后恢复只读模式。这是限定演示故障的验证，不代表所有生产故障或模型响应均可自动恢复。

发布流水线重新运行全量测试、真实 systemd/SSH 集成、签名验证和发行版安装检查。Release 包含两端归档及签名、一键安装脚本和验证公钥；只有所有发布检查通过后才正式发布。

配置、模型接入和恢复检查见[服务异常与 HTTP 恢复闭环](https://github.com/zhuzihan60/agent/blob/v0.5.1/docs/deployment/service-http-recovery.md)。
