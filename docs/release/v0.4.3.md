# A4Diag v0.4.3 发布说明

v0.4.3 在 v0.4.2 的控制端—目标端生产链路上补强了审批、恢复和目标访问安全性。

主要变化：

- HIGH 风险计划可以由审批 CLI 读取并按完整摘要审批，审批前仍保证零执行；审批后由管理员明确运行 `a4diag resume <transaction-id>`。
- 控制端重启后可从持久化检查点恢复事务，不会盲目重放状态未知的写操作。
- undo 后通过签名目标读取验证完整旧状态；证据不足时不会错误地宣告恢复成功。
- 文件替换和 mode 恢复校验覆盖内容、权限与所有权；受保护路径和未授权资源继续 fail closed。
- 目标端 systemd 单元只为管理员声明的文件资源生成受限写入挂载；软件包写入授权仍明确拒绝。
- 告警请求上下文进入诊断证据前会结构化脱敏，中文安装、部署、迁移和验收文档已更新。

## 升级顺序

本版本的控制端恢复校验会向目标端发送 `verify_restored` 字段。为避免旧目标端严格协议校验拒绝新字段，已有 v0.4.2 部署必须按以下顺序升级：

1. 先在每台受控目标上安装 v0.4.3 目标端归档并确认 `a4diag-target-executor.socket` 正常。
2. 再升级控制端到 v0.4.3。
3. 保持 `global_mode: read_only` 完成只读诊断和身份校验后，再恢复既有写策略。

控制端不会自动安装或升级任何目标端组件。管理员必须在准确识别的目标主机上手动执行目标端升级。
