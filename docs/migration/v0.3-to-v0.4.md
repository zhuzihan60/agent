# 迁移指南：从 v0.3 固定目标运行时迁移到 v0.4 通用插件运行时

本指南适用于所有曾运行 v0.3 固定目标运行时的部署。该旧运行时包含 `t_01`、固定 IP、冻结的 systemd 单元允许列表，以及硬编码的只读 SSH 用户。

## 主要变化

- **不再包含固定目标。** v0.3 内置了一个固定目标：位于固定 IP、使用冻结单元允许列表的 `t_01`。v0.4 已移除此行为：目标通过 ID 注册到 v3 settings 文件中，所有告警、MCP 工具和采集器路径都只能通过已注册 ID 解析目标。
- **不按 IP 匹配。** Alertmanager 标签、MCP 工具调用和策略授权都不会按 IP 地址或主机名匹配，也不会回退到配置中的第一个目标。
- **不再硬编码 SSH 用户。** 只读 SSH 用户必须在旧版兼容配置中通过 `ssh_user` 明确指定；源码中没有硬编码用户名。
- **MCP 和采集器使用 v3 运行时。** 只读 MCP 接口由绑定后的插件注册表生成，并通过 v3 运行时的 collector port 采集证据，顺序为：验证身份、获取只读视图、采集。
- **旧权限永远不会自动转换。** v0.3 的固定目标设置、单元允许列表和 IP 允许列表不会被信任，也不会自动导入 v3 settings。`AgentSettings` 只接受 v3 schema，不提供从旧 `Config` 自动转换的路径。
- **旧报告仍可读取。** 报告读取器 `classify_report`、`cleanup_expired` 和磁盘 YAML 布局保持不变，因此 v0.3 报告仍可读取，并继续遵循原有保留策略。

## 必须按顺序执行的迁移步骤

### 1. 备份旧配置和状态

```bash
sudo cp -a /etc/a4diag /var/backups/a4diag-v0.3-$(date +%F)
sudo cp -a /var/lib/a4diag /var/backups/a4diag-state-v0.3-$(date +%F)
```

离线保存 v0.3 配置；v0.4 不会读取它。

### 2. 运行 `a4diag init` 创建全新的 v3 settings 文件

```bash
sudo a4diag init --output /etc/a4diag/config.yaml
```

生成文件的默认值为 `global_mode: read_only`、`targets: []`、`plugins: []`。不要复制 v0.3 配置中的目标区块：两者不兼容，也不会自动转换。

### 3. 逐台注册目标

对原先由固定目标覆盖的每台机器执行：

```bash
sudo a4diag init --input /path/to/target-request.json
```

- 分配新的目标 ID，例如 `target-1`。旧 `t_01` 名称没有特殊意义，也不会继承权限。
- 只授予该机器确实需要的 capability action，并根据已注册插件 manifest 重新选择允许列表，例如 systemd 单元和文件资源。不得导入 v0.3 的旧允许列表。

### 4. 启用任何能力前验证目标身份

写事务开始前，运行时会比较目标实时身份与注册时保存的指纹：

```bash
sudo a4diag approvals list --json
```

- 确认每个目标的 machine-id 和 SSH host key 与注册指纹一致。
- 不匹配时返回 `policy_denied` 或 `target_identity_unavailable`，系统绝不会自动重新注册目标。

### 5. 先完成只读验收

- 保持 `global_mode: read_only` 和 `auto_execute_low: false`。
- 发送带有新 `target_id` 标签的测试告警，确认运行时生成 `read_only`、`read_only_no_model` 或 `policy_denied` 报告，并且插件写调用为零。
- 验证只读 MCP 接口的每次工具调用都只能解析已注册的目标 ID。

### 6. 验收通过后再明确启用写能力

只有所有目标的只读验收通过后，才能执行：

```bash
sudo a4diag init --input /path/to/write-enable-request.json
```

- `write_enabled` 必须在初始化时由管理员输入字面量 `ENABLE` 才能启用。
- HIGH 风险操作仍需要与摘要绑定的 CLI 人工审批。
- 结果未知的操作永远不会自动重放。

## 回滚

- 恢复第 1 步备份的 v0.3 配置和状态，然后重新安装 v0.3 软件包。v0.4 不会写入 v0.3 的配置或状态路径，因此备份保持完整。
- 只有保留 v0.3 报告 schema 时，v0.3 读取器才能读取 v0.4 报告。v0.4 操作报告使用 v3 状态词汇，旧读取器会把它们分类为异常，应将其视为参考信息。

## 禁止事项

- 禁止手工编辑 v3 settings，把 v0.3 目标区块或单元允许列表拼接进去。
- 禁止通过 IP 或“配置中的第一个目标”路由告警及 MCP 调用。
- 只读验收通过前，禁止设置 `global_mode: read_write`。
