# Linux 多类故障修复与 Jev 辅助：设计评审稿

日期：2026-09-22。状态：待用户评审，尚未实现。

## 1. 目标与首版环境

用户要求增加五类修复：磁盘／inode 不足、服务卡死／反复崩溃、容器异常、软件包缺失、DNS／网络配置错误，并接入 Jev 辅助。

成功标准是每类都有实际故障注入、真实执行与独立业务恢复验证；不以模型回答或命令退出码代替恢复证据。保留现有 SSH 身份校验、两端独立授权、签名操作票据、审计和重放保护。

主机暂按此前测试环境设计：Ubuntu／Debian、systemd、APT，DNS 为 systemd-resolved，网络为 Netplan。用户明确要求容器不限于 Docker，并选择了“Podman 或 Kubernetes”；正在澄清需要其中一个还是两者。本稿列出三种适配器的完整边界，未把未答复的选项当成确认。首版不宣称支持 DNF 或 NetworkManager 写入。

## 2. 方案选择

推荐沿用现有插件与事务流程，新增独立能力模块及按需安装的目标端特权 helper。通用执行器保持原有限制，各 helper 只接受已签名、已授权的结构化操作，不接受 shell 文本。

替代方案一：统一交给模型生成 shell；难以限制资源和验证副作用，不采用。替代方案二：接入完整配置管理平台，适合较大机群但引入额外部署和状态系统，本轮不采用。

按共享基础、磁盘、服务、容器、软件包、网络、Jev 七个工作包依次实现，各包单独验收。Jev 不阻塞其他修复模块的开发；无凭据时标记为未做真实联调。

## 3. 授权与事务基础

新增管理员登记的 repair profile，绑定目标、能力、精确资源、允许动作及参数范围、前置条件、恢复检查、频率限制、最大影响预算、有效期及修订摘要。控制端和目标端独立登记，并核对摘要。模型只选择已登记的 profile，不能新增授权资源。

默认仍只读。逐次审批之外增加明确的持续授权，用于用户要求的无人值守修复；持续授权与模型置信度无关，不能下调动作固有风险。危险动作必须在配置中分别开启，泛化的 auto_execute_low 不授予清理、包安装和网络写入权限。授权修订、过期或撤销后，在 prepare、apply 及长任务确认阶段重新核对；不允许借既有事务扩大权限。

将授权 profile 摘要、操作参数、预检查结果摘要、目标身份绑定进计划与操作票据。所有入口（CLI、告警、MCP、恢复重试）走相同授权路径。

新增持久化的资源锁、故障指纹、冷却期和尝试次数统计，重启控制端后仍有效。效果分成可恢复配置、仅可补偿、不可逆三类。不可逆动作失败时可报告部分改变或需人工处理，不能报告 rollback_succeeded。模型无法把不可逆动作改成可逆。

沿用现有执行预算作为短动作上限；APT 等长事务使用持久化 job：请求返回 job ID，后续只查询该 job，超时或断线先 reconcile，不能重新安装。目标端持续记录进度和最终结果；不因 RPC 超时强杀包管理器。

## 4. 磁盘与 inode 修复

动作：清理管理员明确标记为可丢弃的缓存文件。profile 指定精确缓存根目录、最小文件年龄、最大删除文件数、最大逻辑字节数、目标可用空间和 inode 阈值。首版不删除业务数据、不全局 prune、不截断活动日志。

prepare 在目标文件系统内有界扫描，只收集普通文件；不跨挂载、不跟随符号链接，拒绝硬链接及受保护路径。生成按路径、设备、inode、大小、mtime／ctime 绑定的候选清单。apply 通过目录文件描述符安全访问，逐项复核；目录、文件身份或元数据改变则跳过并记录，不能越界扩大扫描。

缓存根必须由管理员控制，清理窗口内停止写入者或持有应用协作锁；无法保证并发边界时拒绝删除，避免仅靠检查后 unlink 的竞态。指定根与授权链的身份同样需要复核。

删除不可回滚，在计划与审计中明确记录。同盘移动文件不算释放容量或 inode。每批后重新读取 statvfs，达到目标即停止；已删除但仍打开的文件可能不释放空间，不能按删除字节数宣告恢复。

在磁盘满之前预留目标端最小事务状态空间，状态写入失败则禁止开始变更；控制端保留对应审计。不能靠删除未知文件为 Agent 自己腾空间。

验收：D 盘承载的独立小型 ext4 镜像中分别耗尽容量及 inode，不填满宿主盘；验证清理、预算终止、并发写入、符号链接、打开文件占用、审计失败，以及空间达标但业务仍失败。

## 5. 服务卡死与反复崩溃

采集 unit 的 InvocationID、主进程身份、Result、退出码、重启计数、受限日志及业务健康检查。active 但连续业务检查失败只能作为异常证据，不能证明卡死根因。

受控恢复动作为已有 start／restart，并增加针对授权 unit 的 reset-failed。只有达到连续失败条件、排除正在进行的修复、且 profile 允许时才执行。默认每个资源十分钟最多一次、每小时最多两次；允许管理员配置更严或显式修改上限。

验证窗口默认至少 60 秒、每 5 秒采样；连续健康、无新增崩溃才报告恢复。窗口与业务请求超时计入事务总预算。再次崩溃时停止自动重启并保留证据，不陷入无限重启。

重启不能恢复进程内存或根治内存泄漏；报告区分“观察期恢复”和根因未消除。回滚只恢复能够证明的配置／启停状态，不承诺恢复旧进程内部状态。

验收：健康端点卡住但进程存活、快速退出循环、启动限流、正常慢启动、重启后仍异常、冷却期内重复告警。

## 6. 容器与 Kubernetes 工作负载修复

### 6.1 Docker

首版支持对登记的现存容器 start／restart，并检查退出码、OOMKilled、RestartCount、Health 和受限日志。绑定完整容器 ID 和登记的镜像摘要；prepare 后同名容器被替换则拒绝。

目标端专用 helper 使用固定 Docker API 操作；控制端与模型不获取 Docker socket，不接受 exec、任意镜像、挂载或特权参数。Docker socket 本身具有很高权限，隔离不能代替 helper 的逐项授权检查。

首次异常可按 profile 重启，观察期内再 OOM／崩溃则停止。首版不删除容器、卷、镜像，不重建容器，不改变内存上限，也不接管编排器管理的实例。

恢复检查包含容器身份、健康状态、重启计数稳定和业务 HTTP／TCP。restart 的状态损失按服务重启处理，不承诺完整回滚。

验收：退出、unhealthy、OOM 后退出、同名替换、重启无效、禁止容器和重复告警；真实 Docker 测试不能用模拟客户端替代。

### 6.2 Podman（待确认纳入）

与 Docker 共用业务恢复约束，使用独立适配器。profile 精确登记运行用户 UID、容器 ID 与存储／运行时归属；rootful 和 rootless 分别授权，不能通过名称在多个用户之间搜索后任意操作。用户 helper 以登记 UID 运行，模型不能传入 UID、socket 路径或环境变量。

独立容器支持 start／restart；由 systemd／Quadlet 管理的容器回到登记的 unit 恢复，避免和控制器竞争。首版不对 Pod 整组重启，也不删除存储卷。真实测试覆盖 rootful、rootless、错误 UID、同名不同用户、健康检查失败和 systemd 管理场景。

### 6.3 Kubernetes（待确认纳入）

首版限定 namespace 内明确登记的无状态 Deployment。绑定可信 API endpoint、集群凭据配置标识、namespace、Deployment UID 与 profile 摘要；更换同名工作负载需重新授权。集群端专用 adapter 持有最小权限 ServiceAccount，接受现有控制端签名票据；凭据不进入模型上下文，不使用 cluster-admin，不授权 Secret 读取、exec 或任意对象写入。

两个受控动作：改变指定的 Pod template 重启注解，触发 rolling restart；把指定容器的镜像恢复到 profile 中登记的已知正确 digest。后一动作只改变允许的 image 字段，不能恢复任意旧 Pod template 以绕过权限。

prepare 读取事件、Pod 状态、RestartCount、Deployment rollout 状态，验证 RollingUpdate 策略、应用允许的可用副本下限和最大不可用预算。对零副本、暂停的 rollout、正在被其他发布修改的对象、无足够容量或不满足预算的对象拒绝自动操作。PDB 不被当作 Deployment rolling update 的自动保护，额外检查 rollout 策略。

apply 使用 UID、resourceVersion 和原字段值前置条件进行精确 patch，冲突则重新诊断，不覆盖其他控制器的变更。进行中的 rollout 使用持久 job 追踪，重复请求不能不断刷新重启注解。GitOps 管理的对象只诊断，除非另行设计并授权通过其声明源修改。

恢复验证：observedGeneration 覆盖本次 generation、更新／可用副本达到期望、旧副本退出、Pod readiness 稳定，且业务检查通过。CrashLoopBackOff 不因重新建 Pod 就算修复；坏镜像可回到登记 digest，配置错误等未支持根因则停止并报告。

失败补偿只恢复本事务改变的字段，且当前值仍为本次写入值；并发变化时报告冲突，不强制覆盖。重启不可能恢复原 Pod 内存。StatefulSet、DaemonSet、Job、节点重启、卷与集群网络修改不在本版范围。

真实验收使用 D 盘隔离测试集群，覆盖可恢复卡死、坏镜像回退、持续 CrashLoop、RBAC 拒绝、同名 UID 替换、并发 rollout、容量不足和控制端断线。

- https://docs.podman.io/en/latest/markdown/podman-restart.1.html
- https://kubernetes.io/docs/concepts/workloads/controllers/deployment/

## 7. 软件包缺失

复用 packages 插件的精确版本表达，但不能直接打开现有安装器被禁止的包写入权限。增加按需安装的 APT helper，由目标管理员登记允许包、精确版本、架构和可信仓库。

仅实现缺失包的 install_exact；不增加常规 remove、升级整机、自动修复任意 dpkg 状态或自动解锁。prepare 解析完整依赖事务，明确列出安装、升级、删除集合；有未授权依赖、既有包升级／删除、锁冲突、未配置完成的 dpkg 状态即拒绝。

先下载并核对可信仓库元数据中的所有包摘要，再冻结事务。apply 使用冻结的本地制品，禁止重新联网求解出不同依赖。安装前复核包数据库和所有依赖状态，发生并发变动需重新准备。记录实际 dpkg 状态与 maintainer script 副作用边界。

APT 安装脚本能产生不可逆副作用；卸载不等同回滚，不自动通过 autoremove 补偿。失败或超时后由 job 状态和包数据库核验已改变集合，报告部分改变及后续人工处理路径。

验证精确安装版本与 configured 状态，再检查依赖该包的业务功能。测试使用自建无害演示包和隔离仓库，验证缺包、缺依赖、被禁止升级、仓库篡改、锁冲突、脚本失败、断线恢复。

## 8. DNS 与网络配置修复

两个动作：对登记链路恢复 systemd-resolved DNS 基线；恢复管理员提供的 Netplan 配置基线。模型不生成任意路由、防火墙或网卡配置。DNS 基线明确服务器、路由域和预期记录，避免仅“能解析”却走错解析路径。

先检测实际管理器；只对已支持的组合执行。WSL 自动生成的 DNS／网络配置不能按普通 Linux 主机处理；不支持时返回原因，不伪称修复。

应用前备份原文件与运行态，校验语法、链路及管理路径，并在目标端持久化超时恢复任务。默认确认期限 120 秒，恢复任务独立于 SSH 与控制端进程；重启后尚未确认的事务先恢复原配置。无法建立可靠恢复任务则禁止 apply。

应用后由控制端重新连接并校验原目标身份；同时由目标端检查 DNS 预期结果和依赖连通性，控制端检查业务。只在全部检查通过后发送绑定事务 ID、配置摘要与单次 nonce 的签名确认；目标端只接受期限内且当前状态匹配的确认。超时、断线或验证失败由目标端自行恢复，再次验证恢复状态。

网络配置恢复本身失败时报告 rollback_failed／unknown，不能以超时任务已执行代替回滚成功。测试不能在承载控制链路的宿主网络上注入故障；用 D 盘独立 Linux 测试机或隔离网络，验证错误 DNS、错误路由、SSH 断开、控制端退出、目标重启和过期确认。

## 9. Jev 辅助决策

新增独立 advisor 接口与 TypeSafe 适配器；现有 DeepSeek diagnose／plan／critic 保留。Jev 通过 POST https://api.typesafe.ai/v1/systemone 接收 state、model、questions，使用 Choice／Score／Noul 的真实结构校验响应。

输入仅包括脱敏证据摘要、程序计算的阈值状态、授权的探针／profile 候选及明确 unknown 选项。输出用于故障类别、补采建议、候选排序和证据矛盾提示；不能创建动作、授予权限、压低风险或宣布业务恢复。

配置模式：off、observe、assist。默认 off；observe 只记录建议；assist 将合格建议交给 DeepSeek，并允许从既有授权探针中选择补采，沿用补采轮数与字节预算。不走 Jev 直接执行修复的捷径。

响应必须包含预期问题 ID、正确类型、候选集合内的选项和有限合法数值。保留概率分布和原始 confidence，不能将其等同于修复正确率。无效响应、超时、429／5xx、未知选项及低置信度均退回现有诊断路径；需要进一步审查的提示不会自动变成允许执行。

独立 API Key 引用，禁止复用 DeepSeek Key；不读取旧密钥值进行探测。不向新服务发送日志，直到用户配置凭据并明确授权发送测试证据。记录实际模型版本、调用耗时、服务商 usage、回退原因与最终业务结果，密钥不进日志。

第一轮 observe 对比同一故障集的 Jev 判断与最终事实，再启用 assist，测试证据不足、混合故障、日志诱导、中文日志、超时及服务不可用。Jev 不可用时关闭辅助不得破坏原有修复能力；不预先承诺节省 token 或提高成功率。

## 10. 集成、兼容与验收

变更涉及 capability 插件、目标 helper／policy、签名协议与清单、初始化和安装器、workflow／policy、审计报告、配置文档与发布验证。新增 helper 权限按 profile 最小化安装，不整体取消现有 executor 的 ProtectSystem 等限制。

现有配置默认关闭新增能力和 Jev；升级不增加任何资源授权。新协议显式协商版本，旧目标拒绝新动作，不能悄悄退回自由命令。备份与恢复授权配置和 helper 单元；升级失败不丢失已有配置。

单元／契约测试覆盖输入约束、授权、参数绑定、预算与状态机；真实集成测试覆盖目标执行权限及安装器；故障注入测试覆盖每类成功、失败、不适用、断线和重启。模拟测试与真实模型／真实操作结果分开记录。

完成条件：五类均有至少一条实际恢复链和一条失败保护链；所有越权负例无副作用；审计能准确区分成功、部分改变和回滚结果；Jev 有真实调用用量与对照结果，或明确标为外部凭据阻塞、不得宣称整项验收完成。

WSL 继续使用 D 盘，不填满 C 盘。普通 WSL 无法代表的 Netplan／网络恢复情形须在独立环境验证。测试后恢复只读设置与演示环境。本任务不自动合并 main、改版本号或发布 Release；完成实现与验收后单独报告。
