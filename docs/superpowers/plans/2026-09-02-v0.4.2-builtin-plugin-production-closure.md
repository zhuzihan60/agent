# A4Diag v0.4.2 Built-in Plugin Production Closure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a signed v0.4.2 whose built-in plugins are installed and attestable, whose SSH target helper executes only signed typed capabilities on the target, and whose complete approval/rollback path passes Linux GitHub Actions.

**Architecture:** The controller installs a release-authenticated built-in catalog and runs model, notification, and target-specific transport instances through systemd sockets. Capability lifecycle calls are routed through the selected transport to an unprivileged target helper and a root target executor; the executor accepts only Ed25519-signed canonical requests and built-in capability methods. All Linux, systemd, SSH, installer, and end-to-end verification runs in GitHub Actions; the Windows workstation is used only to edit, commit, push, and inspect GitHub results.

**Tech Stack:** Python 3.11, Pydantic v2, LangGraph, JSON-RPC over AF_UNIX, OpenSSH, systemd socket activation, Ed25519 from `cryptography`, SQLite, Bash installers, pytest, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-02-v0.4.2-builtin-plugin-production-closure-design.md`

## Global Constraints

- v0.4.2 installs only repository-owned built-in plugins; third-party plugin installation is not a production feature.
- A fresh install has `targets: []`, `global_mode: read_only`, `auto_execute_low: false`, and ten disabled built-in registry pins.
- No release or operation-signing private key may be installed on a target.
- The target bundle is generic and contains no `t_11`, fixed IP, controller address, or environment-specific profile.
- An SSH target capability must never execute through a controller-local `LocalFileAdapter`.
- Raw `command`, `shell`, `script`, `argv`, `cmd`, and `exec` inputs are permanently forbidden.
- SSH, network, DNS, route, firewall, helper, key, audit, user/group, cron, kernel, SELinux, libvirt, qemu, and VM-lifecycle changes are permanently forbidden.
- HIGH has zero effect dispatch before a current digest-bound approval; LOW auto-executes only after both global and target opt-in.
- `execution_unknown` is reconciled and never blindly replayed.
- The implementation must not connect to or modify a real server. Real `t_03 -> t_11` acceptance occurs only after the signed release is published.
- Linux validation runs in GitHub Actions. Do not report Windows-local pytest or compile results as release evidence.
