## 真实模型故障注入（Ubuntu 24.04 WSL，虚拟磁盘在 D 盘）

| 场景 | 实际操作和结果 |
| --- | --- |
| 文件权限错误 | 注入 0600；DeepSeek 诊断、规划、审查；Agent 签名执行 files.set_mode；新鲜且定义绑定的探针确认 0644，事务 succeeded、业务 business_recovered。内容和属主独立复核未改变。 |
| HTTP 服务停止 | 注入 stopped；Agent 执行 services.start；真实 systemd active、HTTP 200 且正文 ready=true，succeeded/business_recovered。 |
| 进程启动但业务不健康 | 演示程序启动后返回 503；Agent apply/verify 完成，但最终 HTTP 检查连续失败；事务 final_verify_failed，签名 undo 将服务恢复原 inactive 状态，rollback_succeeded。未谎报业务恢复。 |
| 权限边界 | 实际控制端 RPC 对未知探针及 /etc/shadow 读取均拒绝。 |

三个模型场景共 9 次 DeepSeek API 调用；服务商 usage 累计 50339 Token（含推理和缓存计数），不是本地估算。模型名称为服务商返回的 deepseek-flash。没有记录密钥。

事务：`wsl-v1-file-1789288314`、`wsl-v1-service-1789288697`、`wsl-v1-rollback-1789289040`。原始报告、usage 和目标端独立台账验证保存在测试机 D 盘 evidence 目录。

WSL 系统更新期间 systemd 从 255.4-1ubuntu8.12 升至 8.17，身份门槛正确拦截旧登记。通过本机、固定 SSH known_hosts、machine-id 和升级日志交叉核对后更新登记，没有跳过校验或重放旧身份事务。

## 验收边界

这是项目已声明能力的验收，不证明任意 Linux 故障均能修复。网络、软件包、容量和资源探针不等于这些领域的自动写入能力。真实模型使用临时加载的候选源码验证，随后实际候选包升级和自检验证部署；正式签名资产由发布流水线再次验证。
